# FanCtl 4.1 计划（v2，4.1-A 完成后的修订）

> 状态：**4.1-A 完成（4.0.1(61) 载体）**；B/C/D/E/F 待数据/择机。方法循环：计划 →
> 对抗审查 → 修订 → 做 → 再审。受众不变（作者本人，GitHub=备份），目的函数不变：
> min(过冲、磨损、能耗、热误差) max(泛化、学习地图质量、可用性)。

## 0. 第一性原理：4.1 的价值锚点

4.0 把能力建出来了（校准、采信域、FNum 自愈、升级链路、三套数据仪表），
但按"存在 ≠ 可信"清点，欠账全部是**证据债**而非功能债：

| # | 欠账 | 性质 | 实测现状（2026-09-11 本机） |
|---|------|------|------------------------------|
| 1 | D 秒基改造与否——预注册裁决无裁决资格 | 控制律决策 | 账本受控时长仅 0.83 天；**P 校准线跨桶不等（fast/slow=6.61）**，按规则须"先修账本再裁决" |
| 2 | 包络健康度观察协议（2-3 周收敛判据）到期未裁决 | 数据修正 | gap 1.43→**0.326**，15 桶 1348 样本，趋势自愈 |
| 3 | 负载锚定评估承诺（功耗直方图满 30 天） | 曲线优化 | 历史战报 30 天满，从未召开评估 |
| 4 | B4a 自升级链路 v3.9.0 建成至今**从未真机验收** | 发行链 | 4.0.0 未打 Release，App 内升级无从触发 |
| 5 | B2 校准只在仿真跑过，真机学习表成熟后路径永不触发 | 迁移韧性 | B2 立项理由（换机/清数据行为悬崖）零真机证据 |

结论：4.1 不加新特性。4.1 的主题是**裁决与验收**——把"建好的"变成"被裁决过/被验收过的"。
每一批都直接落在目的函数上：min(过冲/热误差) ← D 裁决；max(学习地图质量) ← 包络收口 +
冷启动验证；max(可用性) ← 升级链路验收。

## 1. 批次

### 4.1-A dt 裁决前置审计 ✅ 完结（4.0.1(61)，EVOLUTION R17）
**A1 账本生命周期缺陷（代码证实）**：dt 账本原挂 AIControlMetrics，用户切换目标
档位触发评测指标整体重置 → 账本清零陪葬，"≥7 天"门槛结构性不可达。修复 = 独立
持久化 dt-ledger.json（DTLedgerState + startedAt 注入时钟），生命周期 = 控制律
版本，无自动重置。**不迁移 legacy 数据**（修订后口径需要 slopeWeightedSum），
自 4.0.1 重起算。
**A3 两处证伪（比 v1 认知更深）**：①P 校准线前提错误——pDelta=kP·clampedError·dtNom
的每秒贡献依赖各桶平均 error，分桶选择偏差保证桶间不等（真机 4.33/2.68/0.66 是
物理非 bug）→ P 校准线退役；②原规则"D 快/标称比 ≈1 → 关闭"分支不可达（dt 比
按构造 ≈3、斜率比选择偏差保证 ≥1）→ 照原文裁决会无条件改秒基。修订 = 账本新增
slopeWeightedSum（只认 D 出力拍）→ I_D 工具把原始比分解为斜率效应 × dt 效应；
VM 复现测试锁定 **I_D 比 = 3.00 精确** + P 线不等复现。
**A2 口径定版**：裁决门槛 = 受控时长 ≥7 天（三桶 seconds 之和，自 4.0.1 起算）
且快拍秒占比 >5%；裁决方法 = 占比确认 + VM 危害测试（同轨迹对比现行律 vs 秒基
律），账本只供暴露度。
**DoD 达成**：档位切换保留账本 + 重启恢复 + 双向兼容（旧 JSON 忽略遗留键 / 回滚
4.0.0 读不到账本字段不炸）+ fuzz 读出侧安全域，断言 4469→4491。

### 4.1-B 包络收口裁决（9 月下旬，观察协议到期）
判据（沿用 v3.6 观察协议）：gap 持续 →0 则**确认自愈、关闭议题**；若不收敛 →
一次性数据修正（学习数据手术，非控制律）。当前 0.326 趋势向好，大概率前者。
**联动**：若走数据手术 → 清桶即触发 B2 校准真机首跑（见 D），一次动作两份证据。

### 4.1-C 负载锚定评估（数据已就绪，随时可开）
功耗直方图 30 天满。按优化器负载锚定的既定口径评估：温度分位下移而功耗分位未变
= 自降温 → 禁止锚点跟进。产出 = 评估结论记账（做或不做曲线修正，数据说话）。

### 4.1-D 真机冷启动 dogfood（A 完成后择机，需一个低负载窗口）
**这是 B2 立项理由的首次真机验证**：备份 learn.json → App 重置学习数据 → 观察
B2 校准全生命周期真机首跑（观察期 auto 采样 → 2 桶/12 样本接管）→ 对照判据。
**预注册判据（先于实验写下）**：接管后过冲不劣于 4.0 HIL 基线容差（+1.5°）、带内
时长不低于 95%；校准日志链完整（校准中→采样→完成/超时→接管各一次）。
**附带观察项**：fan0/fan1 转速差实测（4.0 审查遗留的采样器 fan0-only 偏差，本实验
顺带取数，不单独立项）。
**裁决**：通过 → 保留重学表（学习数据本来就该重新积累）；不通过 → 恢复备份 + 缺陷
回灌修复。**备份文件保留到 4.1-F 之后**。

### 4.1-E D 秒基改造（条件批次：仅当 A 修订后的裁决触发）
控制律变更 = 4.1 内最高风险项。三重验证门槛（预注册规则原文）：VirtualMachine 验
3s 拍严格等价 + HIL 冷启动对比 + 81 族扫描零劣化。**禁止在账本数据不达标时动**。

### 4.1-F 发版 + B4a 首验收（收官）
tag 4.1.0 → Release（CI 资产）→ **真机 App 内点一次升级**（v3.9 建成以来首次真实
使用）：下载→校验→授权→watcher 重启全链路。任何 P1 → 修复回灌 4.1.1，验收记录
入 EVOLUTION。**此批次是 4.1 存在的理由之一：没有发版，B4a 永远是欠账。**
