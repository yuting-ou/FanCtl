# FanCtl 4.0 计划（v2，经一轮五轴对抗审查修订）

> 状态：批次 1 已开工。本文是 4.0 的持久计划基线——每批完成勾账，偏离计划必须有
> EVOLUTION 记账。方法：计划 → 对抗审查 → 修订 → 做 → 对产物再审 → 循环。

## 0. 第一性原理

目的函数继承自优化器适应度向量：**min（过冲、磨损、能耗、热误差）max（泛化、学习地图质量、可用性）**。

3.x 的账本证明四个 min 轴已到"可裁决"水平（族扫描零违例、包络 5.8→1.43、启停磨损 -90%）。
两个 max 轴基本未动：泛化（一切标定/验证来自一台 M2 Pro）与可用性（分发链有 Gatekeeper
摩擦、更新闭环未真实走通）。**4.0 = 攻 max 轴，主题一句话：从 N=1 到 N=任何人。**

泛化的第一性拆解——一台陌生 Mac 上产品要"对"，需要三层：
1. **感知对**：传感器拓扑/功耗键发现 → 硬件画像已落地（v3.8，第一块砖）✅
2. **行为对**：控制标定随热质量/风扇权限而异 → 冷启动校准 ❌（本计划核心）
3. **表达对**：能力边界诚实展示（无风扇机器的期望管理）❌

## 1. 批次（顺序即依赖）

### B1 冷却能力分级与诚实形态
- 冷却分级：`fanCount == 0 → passive`，否则 `active`（来源：FanController FNum 防御性
  解析已有，零成本）
- daemon 门控：passive 机器上所有控制模式语义化为 auto（复用 boost 过期的同源路径，
  零新引擎状态）；边沿日志一次性说明
- App 表达：模式选择处显示"此机型无风扇，由 macOS 管理"（诚实文案，不做推荐引擎）
- **DoD**：MockSMC 零风扇全链路断言（引擎启动/不写扇/不崩/状态可解释）；有风扇行为
  零变化（全量回归）；旧 status.json 解码兼容
- **回滚**：门控是纯 daemon 分支，revert 即回现状

### B2 冷启动校准期
- 校准状态机（daemon 侧，单一数据源）：观察（只采样不控制，风扇归系统）→ 初始化
  （热经验表/ThermalModel 用实测种子）→ 进入控制；可退出
- 校准账本**独立**于主学习表——晋升门仍走 sanitize，不放宽任何污染阈值
- learn/thermal-model 文件加 `schemaVersion`（decodeIfPresent 默认 0），为未来演进铺路
- HIL 验证：VirtualMachine 冷启动轨迹 vs 现状（直接控制）对比，过冲/收敛不劣化
- **DoD**：校准全生命周期引擎测试；HIL 数字入 EVOLUTION；退出路径断言
- **回滚**：校准期故障 → 跳过初始化直接进入现状行为

### B3 泛化边界量化（研究项，非用户功能）
- 把 B2 的冷启动产物注入 81 成员族扫描，量化"哪类机器可安全泛化、哪类必须重新校准"
- 产出：边界报告进 EVOLUTION；**不做**用户级学习数据导入/导出（违反"移植即污染"原则）
- **DoD**：报告 + 族扫描零违例

### B4 发行信任链
- 4a（不阻塞）：自升级首验收——v3.9.1 → v4.0 真实点一次菜单升级
- 4b（阻塞于决策点①）：Developer ID 签名 + notarization 进 CI（notarytool）；
  自升级校验门增加签名验证
- **DoD**：Gatekeeper 双击可开；自升级端到端成功

### B5 数据裁决（只裁决，无数据支撑不改）
- dt 账本裁决（预注册规则，2026-09-15 满足 ≥7 天；当前比值 7.75 vs 理论 3、
  P 基线比 1.44 vs 理论 1——两条线都待裁决，先积累）
- 包络收敛确认（观察协议 2-3 周，9 月下旬到期）
- 优化器按负载锚定（功耗直方图已满 30 天，可评估启动）
- **DoD**：每项独立裁决书进 EVOLUTION，结论可以是"不改"

## 2. 明确不做

- 不动 92°/SSD/电池安全红线；新能力全部从"红线之上的覆盖"实现
- 不换 UI 设计语言（v3.4 双玻璃卡为用户钉死标准）
- 不引入神经网络/云服务（AI=自适应控制的诚实边界）
- 不做用户级学习数据移植（移植即污染）
- 英文 UI 移出 4.0（单独小版本，防范围膨胀）

## 4. 决策点（用户）

1. **Apple Developer 账号**（$99/年）→ B4b 前提；不办则 4.0 保留右键打开的发行形态
2. **第二台 Mac**：有则 B3 研究项升级为真机对账；无则按 MockSMC+族扫描+社区征集
3. B1 起每批完成是否立即推送发版，还是攒到 4.0 一起发（默认：攒批，4.0 一次发）

## 5. 纪律（继承）

每批：断言下限只升不降（当前 4420）、族扫描必跑、EVOLUTION 记账、最小 diff、
修完再审（修复是新的攻击面）。
